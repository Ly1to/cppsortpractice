# 项目如何测量函数调用耗时

一次函数调用耗时就是调用开始到调用返回之间经过的时间。本项目的计时实现位于 [`src/main.cpp`](../src/main.cpp) 的 `runTimedFeeSort` lambda 中，目前用于测量以下三个费用排序函数的调用：

- `mergeSortByFee`
- `insertionSortByFee`
- `shellSortByFee`

项目没有引入第三方 benchmark 库，也没有使用 profiler；它直接使用 C++11 标准库提供的 `std::chrono::steady_clock`。

## 核心代码

计时部分可以简化为：

```cpp
std::vector<Ride> workingRides = rides; // 准备输入，不计时

const auto startTime = std::chrono::steady_clock::now();
sortFunction(workingRides);
const auto endTime = std::chrono::steady_clock::now();

const double elapsedMilliseconds =
    std::chrono::duration<double, std::milli>(endTime - startTime).count();
```

`sortFunction` 是指向具体排序函数的函数指针。例如菜单选项 `1` 传入 `mergeSortByFee`，选项 `2` 传入 `insertionSortByFee`，选项 `3` 传入 `shellSortByFee`。因此，三个排序算法共用同一套计时逻辑。

## 测量过程

1. 把原始 `rides` 复制到 `workingRides`。复制发生在计时开始前，避免排序修改原始数据，也避免把输入准备时间算进本次调用。
2. 调用 `steady_clock::now()` 保存开始时间。
3. 通过函数指针执行 `sortFunction(workingRides)`。
4. 函数返回后再调用一次 `steady_clock::now()` 保存结束时间。
5. 将两个时间点相减，再把得到的时长转换为毫秒。
6. 使用 `std::fixed` 和 `std::setprecision(3)` 输出三位小数，例如 `归并排序耗时：1.234 ms`。

上面的代码用公式表示就是：

```text
调用耗时（ms） = (endTime - startTime) 转换为毫秒
```

`std::chrono::duration<double, std::milli>` 完成单位转换，`.count()` 取出以毫秒为单位的数值；模板参数 `double` 保留了小数部分。

## 计时边界

`runTimedFeeSort` 测量的是开始和结束两个时钟采样时刻之间的实际经过时间，也就是 wall-clock time。当前边界如下：

| 操作 | 是否计入显示耗时 |
| --- | --- |
| 复制 `rides` 到 `workingRides` | 否 |
| 进入并执行 `sortFunction` | 是 |
| 函数指针的调用开销 | 是 |
| 排序函数调用 `printTopFeeRides` 并输出前 20 条记录 | 是 |
| 输出“...耗时：... ms” | 否 |
| `workingRides` 在 lambda 结束时的析构 | 否 |

需要注意，三个费用排序函数都在自身末尾调用 `printTopFeeRides`。因此，菜单中显示的数值并不等同于纯排序算法耗时，而是“排序 + 格式化并输出前 20 条记录”的总耗时。如果希望比较算法本身，应先让被测函数只完成排序，再单独执行输出。

## 为什么使用 `steady_clock`

`steady_clock` 是单调时钟，适合测量时间间隔：

- 它不会因为系统日期或时区变化而倒退。
- 两个时间点相减得到的是 `duration`，可以直接换算为秒、毫秒等时间单位。
- 它表示经过时间，不适合用来记录具体日期或时刻。

不同操作系统和硬件上，时钟的实际分辨率可能不同。代码把结果输出到三位小数表示显示精度，不代表测量一定精确到 0.001 毫秒。

## 如何复现

在项目根目录构建并运行：

```sh
make
./build/OrdCsltion rides_1k.txt
```

随后输入 `1`、`2` 或 `3`，程序会分别调用归并排序、插入排序或希尔排序，并输出类似：

```text
归并排序耗时：x.xxx ms
```

也可以用其他数据文件运行：

```sh
./build/OrdCsltion rides_10k.txt
```

比较算法耗时时，应保证数据文件、编译选项和运行环境一致，并多运行几次观察波动。

## 结果如何理解

当前实现是单次测量的便捷计时方式，适合在交互菜单中快速观察不同实现的大致速度。它没有预热、重复运行或统计中位数，因此单次结果可能受到以下因素影响：

- CPU 负载和频率变化；
- 进程调度；
- `std::cout` 的格式化、缓冲和终端性能；
- 不同机器、编译器及优化选项。

此外，`steady_clock` 测量的是程序看到的时间流逝，不是进程实际占用的 CPU 时间。若需要更严格的性能比较，应把被测逻辑与输出分离，多次运行并统计均值、中位数或分位数。
